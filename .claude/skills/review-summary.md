# Skill: review-summary

## 描述
在完成一次代码修改后，输出结构化的改动摘要，帮助用户快速理解变更、评估风险，并决定是否合入。

## 触发条件
- 完成一个功能或修复的代码编写后
- 用户要求"review"、"总结改动"、"出个摘要"等

## 输出格式（必须严格遵循）

```markdown
# 改动摘要

## 一、修改文件列表
- `path/to/file1` - 新增/修改/删除
- `path/to/file2` - 新增/修改/删除

## 二、每个文件的修改详情
### `path/to/file1`
- 修改前：
- 修改后：
- 修改原因：
- 影响面：

### `path/to/file2`
...

## 三、兼容性检查
- [ ] 接口返回结构是否改变？（若是，说明影响哪些调用方）
- [ ] 数据库 schema 是否改变？
- [ ] 现有功能是否退化？

## 四、异常处理
- 是否所有异常分支都有处理？
- 是否有未捕获的潜在错误？

## 五、重复逻辑检查
- 是否存在与已有功能重复的代码？
- 是否抽取了公共函数？

## 六、潜在风险
- （列举可能引入的新问题或对边界情况考虑不足之处）

## 七、测试建议
- 建议重点测试的场景
- 建议执行的测试用例

## 八、改动是否超出原始任务单的范围？
- 是 / 否（如果是，列出超出的部分）
```
